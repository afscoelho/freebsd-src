# How to Submit Changes to FreeBSD for Review

These instructions are tailored to this repository and the `hwpmc-tsc-logging` change set,
but apply generally to any small userland change submitted via GitHub PR.

---

## Step 0 — Read the AI policy first

**This is mandatory before anything else.**

From the FreeBSD contribution guidelines:

> *"Changes generated by AI tools without substantial human review and validation are
> explicitly rejected by the project."*

Before submitting you must:
- Understand every line of every diff yourself — not just trust that the AI got it right
- Be prepared to defend and explain the change during review as if you wrote it
- Do not mention AI assistance in the commit message or PR description

---

## Step 1 — Verify the change is correct and complete

Read each diff carefully:

```sh
git diff lib/libpmc/pmclog.h
git diff lib/libpmc/pmclog.c
git diff lib/libpmc/libpmc_json.cc
git diff usr.sbin/pmcstat/pmcstat.h
git diff usr.sbin/pmcstat/pmcstat_log.c
```

Questions to answer before submitting:
- Is `pl_ts` still needed by any other caller? (`grep -r pl_ts lib/ usr.sbin/`)
- Is `_pmcstat_current_tsc` thread-safe? (pmcstat is single-threaded in log-replay — yes)
- Does the JSON output break any downstream consumers that parse it?

## Step 3 — Build and smoke-test

```sh
export NCPU=$(sysctl -n hw.ncpu)
export FBSD_DEV=/home/andasilv/dev/freebsd

# Full rebuild (required for lib/ changes)
make -j${NCPU} buildworld

# Smoke-test with the freshly built binaries (no install needed)
OBJBASE=$FBSD_DEV/obj/home/andasilv/dev/freebsd/wt/custom/amd64.amd64
pmcstat -S instructions -O /tmp/pmc.log sleep 1
env LD_LIBRARY_PATH=$OBJBASE/lib/libpmc \
    $OBJBASE/usr.sbin/pmcstat/pmcstat -R /tmp/pmc.log | head -20
```

Verify that:
- The first column of every output line is a plausible TSC value (billions range for a GHz CPU)
- The `initlog` line shows a `tsc_freq=` value matching your CPU frequency
- No crashes or assertion failures

## Step 4 — Choose the submission channel

| Change size | Channel |
|-------------|---------|
| ≤10 files, <200 lines | GitHub PR against `freebsd/freebsd-src` main |
| Larger, complex, or controversial | Phabricator (`reviews.freebsd.org`) |

This change set is 5 files / ~21 lines net — use a **GitHub PR**.
Do **not** open a Phabricator review for the same change simultaneously.

---

## Step 5 — Craft the commit

The FreeBSD commit format:
```
component: one-line summary in imperative mood

Body explaining *why*, not just what. Reference any relevant
context, prior art, or bugs.

Trailers
```

Stage the files and commit with `-s` (adds `Signed-off-by:` automatically):

```sh
git add lib/libpmc/libpmc_json.cc \
        lib/libpmc/pmclog.c \
        lib/libpmc/pmclog.h \
        usr.sbin/pmcstat/pmcstat.h \
        usr.sbin/pmcstat/pmcstat_log.c

git commit -s
```

Example commit message (rewrite in your own words):

```
pmclog/pmcstat: expose raw TSC in parsed events and log output

The pmclog record header stores the TSC (Time Stamp Counter) in pl_tsc,
but the existing userland parser shoehorned this value into pl_ts.tv_sec,
a struct timespec field that is semantically wrong for a raw cycle counter.

Add a dedicated uint64_t pl_tsc field to struct pmclog_ev and populate it
from the record header. Mark pl_ts as deprecated; it is preserved for ABI
compatibility and assigned the same raw TSC value as before.

Fix a related bug in libpmc_json.cc where the TSC was formatted with %jd
(signed) instead of %ju (unsigned), and was read from the wrong field.

Update pmcstat -R output to print the raw TSC as the first column of every
decoded log entry and to include tsc_freq from the INITIALIZE record. This
gives analysts the data needed to convert TSC deltas to wall-clock time:

    elapsed_ns = (tsc_end - tsc_start) * 1e9 / tsc_freq

MFC after:      2 weeks
```

---

## Step 6 — Push and open the PR

```sh
# Push the branch to your origin fork
git push origin hwpmc-tsc-logging

# Open the PR
gh pr create \
  --repo freebsd/freebsd-src \
  --head <your-github-username>:hwpmc-tsc-logging \
  --base main \
  --title "pmclog/pmcstat: expose raw TSC in parsed events and log output" \
  --body "$(cat .github/PULL_REQUEST_TEMPLATE/pull_request_template.md)"
```

Fill in the PR body template — at minimum:

```
Tested by:   <your name> (buildworld + pmcstat -R smoke test on amd64, FreeBSD 16.0-CURRENT)
MFC after:   2 weeks
```

Delete template lines that do not apply.

---

## Step 7 — After opening the PR

- CI runs automatically — watch for style or build failures and fix promptly
- FreeBSD reviewers may ask questions; respond thoroughly and in a timely manner
- To amend after review feedback:
  ```sh
  git commit --amend
  git push --force-with-lease origin hwpmc-tsc-logging
  ```
- Do not open a Phabricator review while the GitHub PR is open
